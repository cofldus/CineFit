## 2. 수집 우선순위와 단계별 전략

**MVP (수동 중심)**
1. 영화 메타: KOBIS+KMDb 자동 동기화(일 1회 배치, ETag/조건부 요청).
2. 영화 기술 사양: 개봉 4주 전부터 공식 발표·보도자료·매체 기사 **관리자 수동 입력**(observation으로).
3. 상영관 사양·좌석: 대상 50~100관을 관리자가 공식 페이지·현장 확인·커뮤니티 교차로 검증 입력.
4. 회차: 핵심 관 위주 관리자 주간 수동 입력 + "공식 예매 페이지에서 최종 확인" 문구 + 딥링크.
   딥링크는 체인별 URL 템플릿(`cinema_chains.booking_url_template`) 사용.

**베타 이후 (자동화 확대)**
5. KOFIC 상영스케줄 개방 요청/극장 제휴 협상 병행 — 성사 시 파서를 공식 피드로 대체.
6. 뉴스 모니터링 봇(리뉴얼·개관·폐점 키워드) → 관리자 알림 큐.

## 3. 파서·배치 구조

```
scheduler(cron) → job queue(BullMQ) → fetcher(레이트리밋·UA 명시·ETag 캐시)
  → parser(소스별 모듈, 단위 테스트 필수) → validator → observations 적재
  → (자동 승격 규칙 통과 시) 대표값 갱신 → 캐시 무효화
실패 시: 지수 백오프 재시도 3회 → 실패 알림(관리자) → 파서 상태 대시보드 반영
구조 변경 감지: 응답 스키마 해시·필드 커버리지 급변 시 자동 중단+알림 (조용한 오염 방지)
중복 방지: content_hash 비교, showtime 자연키(관+시각+영화) upsert
```

## 4. 검증 규칙 (validator)

- 형식: 시간대(KST) 정규화, 자정 넘는 회차 처리, 러닝타임 대비 종료 시각 정합.
- 논리: 폐점 관에 회차 금지, 영화 개봉 상태와 회차 날짜 정합, 관 브랜드와 회차 포맷 정합
  (일반관에 IMAX 회차 → 오류 큐).
- 급변 감지: 가격 ±50% 변동, 좌석 수 변경, 관 명칭 변경 → 자동 승격 금지, 검수 큐.

## 5. 준수·거버넌스 체크리스트

- [ ] 소스 추가 시 robots.txt·약관 검토 기록을 `sources.terms_note`에 필수 기재
- [ ] 로그인·보안장치·유료벽 뒤 데이터 수집 금지
- [ ] 요청 빈도 상한: 동일 호스트 분당 ≤ 6회(수동 검증 보조 용도 한정), 심야 배치 우선
- [ ] 원문 전체 저장 지양 — 사실 필드만 구조화, 원문은 링크+해시
- [ ] 커뮤니티 문장 재게시 금지, 요약·수치화만
- [ ] 삭제 요청 처리 절차(72시간 내) + `sources.allowed_use` 갱신
- [ ] 파서별 단위 테스트·픽스처(HTML 구조 변경 시나리오 포함, 문서 11 §3)
- [ ] 데이터 품질 대시보드: 신선도, 커버리지, 충돌 수, 파서 실패율
