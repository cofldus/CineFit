# 문서 11. 테스트 계획

- 조사 기준일: 2026-07-27 | 서비스: CineFit(시네핏)

## 1. 추천 품질 평가

- **골든 데이터셋**: (영화×사용자 조건×후보 회차×전문가 정답 순위) 30케이스로 시작, 100케이스 목표.
  케이스 구성: 특별관 유리작(스펙터클), 특별관 무익작(대사 드라마), 접근성 필수, 멀미 민감,
  가격 제약, 정보 결손(확장비 미확인), 출처 충돌 포함 — 의도적으로 어려운 케이스 50% 이상.
- 지표·게이트: Top1 일치율 ≥ 60%, Top3 포함률 ≥ 85%, NDCG@3 ≥ 0.8 (MVP 게이트, 문서 3 §7).
- 운영 지표: 추천 후 사용자 선택률, 딥링크 CTR, 관람 후 만족, 재사용률, "이유를 이해했다" 설문.

## 2. 사실성 평가 (자동 회귀 테스트 9종 — 배포 게이트)

| # | 금지 오류 | 테스트 방법 |
|---|---|---|
| 1 | 미개봉작 관람평 생성 | status=upcoming 영화 상세·추천 응답에 리뷰 텍스트 부재 assert |
| 2 | 존재하지 않는 상영 포맷 | 응답 포맷 ∈ movie_format_versions 검증 |
| 3 | Atmos관 ↔ Dolby Cinema 혼동 | 사운드만 Atmos인 관이 Dolby Cinema로 표기되지 않음 |
| 4 | IMAX관 존재 ↔ IMAX 회차 혼동 | presentation 없는 회차에 IMAX 라벨 부재 |
| 5 | 과거 사양을 현재로 표시 | valid_to 마감 사양이 현재 화면에 미노출 (리뉴얼 픽스처) |
| 6 | 화면비 루머의 확정 표시 | info_status=rumor/unverified 값에 확정 배지 부재 |
| 7 | 국가별 개봉일 혼동 | KR release만 "국내 개봉"으로 표기 |
| 8 | 타 지점 사양 혼합 | 동명 브랜드 2개 관 픽스처에서 사양 교차 오염 없음 |
| 9 | 동명 이작 혼동 | 같은 제목 다른 연도 영화 검색 분리 |

LLM 사용 경로(질의 파싱·설명 정리)는 인용 없는 사실 문장 제거 필터의 단위 테스트 + 주기적 수동 감사.

## 3. 파서·배치 테스트

픽스처 기반: HTML/JSON 구조 변경, 빈 데이터, 중복 회차, KST/자정 넘김, 매진 표기, 관명 변경,
특별관 표기 차이("IMAX LASER" vs "IMAX"), 비정상 가격, 스테일 캐시(ETag), 403/429 차단, 네트워크 실패.
계약 테스트: KOBIS/KMDb 응답 스키마 스냅샷 — 필드 커버리지 급락 시 CI 경고.

## 4. 단위·통합·E2E

- 단위: recommender 축별 스코어러(경계값·결측), 이력 모델 승격 규칙, 충돌 해결 규칙.
- 통합: 추천 API 전체 파이프라인(시드 DB), 관리자 승인→대표값 갱신→캐시 무효화.
- E2E(Playwright): 빠른 추천 5입력→3카드→좌석→딥링크 / 오류 제보 / 접근성 필터 시나리오.

## 5. 접근성·보안·성능

- 접근성: axe 자동 검사(심각 0), NVDA/VoiceOver 수동 3시나리오(추천 결과 낭독, 좌석 요약, 배지 의미 전달).
- 보안: 인증·RBAC 테스트, 속도 제한, 입력 검증 퍼징, EXIF 제거 검증, API 키 미노출 스캔, 신고 악용(대량 신고) 시뮬레이션.
- 성능: 추천 p95 < 2s(후보 200회차 부하), 검색 p95 < 500ms, 배치가 조회에 주는 영향 측정.

## 6. 데이터 최신성 모니터링(테스트가 아닌 상시 게이트)

- 핵심 50관 중 30일 초과 미확인 비율 > 20% 시 대시보드 경고 + 신규 추천에 자동 Freshness 감점 동작 검증.

## 7. 사용자 테스트 (알파)

그룹: 특별관 마니아 / 일반 관객 / 저빈도 관객 / 4DX 멀미 민감 / 자막 가독성 중시 / 차량 / 대중교통 / 접근성 기능 사용자 — 각 2~3명.
과업: "이번 주말 [지정 영화]를 보러 갈 곳을 정하라". 측정: 완료 시간(목표 3분), 추천 이유 이해도,
신뢰 배지 인지, 오탐(잘못된 정보 발견 시 신고 흐름 사용 여부). 인터뷰로 가중치 프리셋 보정.
