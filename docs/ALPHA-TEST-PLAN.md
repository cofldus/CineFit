# 알파 테스트 계획 (R21 — 5명 사용자)

목표: **실제 회차를 제한적으로 운영하는 상태**에서 5명이 추천 플로우를 끝까지 사용하게
하고, 단계별 이탈·추천 품질 신호를 trace·analytics로 수집한다. 정책은 `v3-axis100`
동결 상태로 진행한다(테스트 도중 점수·가중치 변경 금지).

## 1. 사전 준비 (운영자)

1. **회차 데이터**: `db/fixtures/alpha-showtimes.template.csv`를 복사해
   - 영화 3~5편, 서울 핵심 극장 8~12곳(관), **오늘부터 3일 범위**로 날짜·시각을 채운다.
   - 각 행은 **극장사 공식 예매 페이지에서 사람이 직접 확인**한 값만 넣는다 —
     `sourceUrl`(확인한 공식 페이지 URL)과 `checkedAt`(확인 시각)은 필수.
     템플릿의 `example.invalid` placeholder를 실제 URL로 반드시 교체할 것(가짜 데이터 금지 원칙).
   - `/admin/showtimes/import`에서 **미리보기 → 오류 행 수정 → 등록**.
2. **만료 확인**: 매일 `npm run maintenance:daily`(또는 Vercel cron)가 지난 회차를
   비활성화 + `verification_status='expired'` 처리한다. 테스트 기간 중 매일 아침
   당일 회차를 재확인·보충한다(마지막 확인 7일 초과 시 stale 표시가 뜬다).
3. **환경**: `CINEFIT_ALLOW_SYNTHETIC` 미설정(기본) — 관리자 확인 회차가 있으면 합성
   데이터는 자동으로 제외된다. 필요 시 `private_alpha_gate` 켜고 초대 코드 발급
   (`/admin/invite-codes`).

## 2. 테스트 시나리오 (참가자 5명 공통)

각 참가자에게 안내하는 과업 — 화면을 공유하거나 옆에서 관찰하며, 막히는 지점을 기록한다.

1. **T1 기본 흐름**: 홈 → 영화 선택 → 조건 입력(자유) → 추천 결과 확인.
   질문: "1위 추천이 왜 1위인지 화면만 보고 설명할 수 있나요?"
2. **T2 조건 변경**: 결과에서 '조건 수정하기' → 시간대·이동 한도를 바꿔 재추천.
3. **T3 좁은 조건**: 이동 한도 30분 + 특정 시간대로 후보 0개를 만들고,
   완화 제안(+N개)을 눌러 복구하게 한다.
4. **T4 공식 확인**: 1위 카드에서 공식 예매/상영시간표 링크로 이동해
   "실제 상영시간표와 일치하는지" 확인하게 한다.
5. **T5 피드백**: 도움됐어요/아쉬워요 + 이유 제출.

## 3. 수집 데이터 (자동)

- **단계별 이탈·완료율**: `/admin/alpha-ops` 사용 퍼널
  (app_opened → movie_selected → step1~3 → recommendation_generated → feedback).
- **공식 링크 클릭률 / 도움됨 비율 / zero result 조건 / 정책 버전별 결과**:
  `/admin/alpha-ops` 추천 품질 지표.
- **개별 실행 재현**: `/admin/runs` → 실행 상세(퍼널·제외 사유·4축 점수·soft 감점).
- 위치 좌표·주소·자유 입력 원문은 이벤트에 저장되지 않는다(`src/analytics/analyticsEvents.ts`).

## 4. 성공 기준

| 지표 | 기준 |
|---|---|
| 추천 완료율 (step1 진입 → recommendation_generated) | ≥ 80% (5명 중 4명 이상) |
| T1에서 "왜 1위인지" 설명 가능 | 5명 중 4명 이상 |
| T3 완화 제안으로 후보 복구 성공 | 5명 전원 |
| 공식 링크 클릭률 (추천 생성 세션 대비) | ≥ 60% |
| 추천 결과와 실제 상영시간표 불일치 | 0건 (발견 시 즉시 해당 회차 수정·기록) |
| 도움됨 비율 | ≥ 60% (미달 시 사유 태그를 R22 입력으로) |
| 치명 버그(진행 불가) | 0건 |

## 5. 종료 후

- `/admin/alpha-ops` 수치 캡처 + `/admin/runs`에서 특이 실행(zero·불일치) trace 보관.
- 참가자별 관찰 메모를 이슈로 정리(개인 식별 정보 제외).
- 정책 변경이 필요하면 **v4 정책 버전을 새로 만들어** 비교한다(v3 무버전 수정 금지 —
  docs/POLICY-V3-AXIS100.md).
