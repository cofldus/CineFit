# 베타 한계 (사용자·운영자에게 투명하게 공개할 항목)

- 기준일: 2026-07-28 (7차 마일스톤 갱신)

## 데이터

- 회차·가격은 **검증용 합성 데이터**다. 관리자가 공식 예매 페이지에서 확인해 등록한
  회차만 실제 예매 딥링크를 제공하고, `RecommendCard`·상영관 상세에 항상
  "≈ 검증용 합성 회차" / "✔ 관리자 확인 회차" 배지로 구분된다.
- 상영관 사양은 조사 자료(공식 사이트·언론·커뮤니티) 기반이며 출처·확인일·신뢰도가
  항상 함께 표시된다. 사용자 제보는 관리자 검토·승인을 거쳐야만 반영된다
  (`docs/DATA-PROMOTION-POLICY.md`).
- 잔여 좌석은 수집하지 않는다 — 좌석 존 추천은 항상 "추정"이며, 실제 예매 가능 여부는
  공식 예매 페이지에서 확인해야 한다.
- KMDb API 키 미발급 — KOBIS 단일 출처로만 운영 중. KOBIS 약관도 상업적 사용 범위가
  조항 간 상충해 출시 전 KOFIC 서면 확인이 필요하다(`docs/90-verification-register.md`).

## 인프라

- SQLite는 개발·로컬·셀프호스트(단일 노드, 영속 볼륨) 전용이다. 서버리스·다중 인스턴스
  운영 배포는 PostgreSQL 필수(`CINEFIT_ENV=production`이 강제, `docs/DATABASE.md`).
- 셀프호스트 + SQLite + 리눅스 조합에서 드문 쓰기-직후-읽기 지연 현상을 테스트 중
  발견했다(근본 원인 미확정) — `docs/TESTING.md` §4 참고. 다중 사용자 동시 접속이 잦은
  셀프호스트라면 PostgreSQL 이전을 권장한다.
- 관리자 인증은 단일 비밀번호 + HMAC 쿠키(1인 운영 전제). 다중 운영자·감사 추적이
  필요해지면 검증된 인증 라이브러리로 교체해야 한다.

## UI/UX

- 이번 마일스톤에서 새로 그린 화면은 홈/영화 선택/조건 입력/추천 결과/상영관 상세/
  출처/제보뿐이다. 원 설계 문서(`docs/09-ux-ui.md`)가 구상한 온보딩·영화 검색·
  마이페이지·좌표 기반 SeatMapViewer는 애초에 구현되지 않아 이번에도 다루지 않았다.
- CompareTable 모바일 카드형(속성별 비교)은 1차 구현이다 — 상영관명이 각 속성 블록마다
  반복돼 다소 빽빽하다. 데스크톱 3열 표는 문제없다.
- 관리자 화면은 레거시 CSS(`.card`/`.btn`/`.badge`)를 유지한다 — 색 대비만 수정했고
  전체 시각 언어를 사용자 화면과 통일하지는 않았다(의도적 범위 제한, `docs/DEVELOPMENT.md`).
- 시각 회귀 테스트(`e2e/visual.spec.ts`)는 리눅스 컨테이너 베이스라인과 2% 픽셀 차이
  허용치로 설정돼 있어, 작은 배지 텍스트 색상 변경처럼 국소적인 변화는 갱신 없이
  통과할 수 있다 — 색 대비처럼 수치로 검증해야 하는 변경은 `e2e/accessibility.spec.ts`
  (axe-core)가 실질적인 게이트다.

## 접근성

- WCAG 2.2 AA를 목표로 axe-core 자동 검사(라이트·다크 × 10화면, 위반 0건)와 스킵 링크·
  포커스 링 수동 확인을 마쳤다(`docs/ACCESSIBILITY.md`). 다만 자동 검사는 대비·라벨
  누락 등 기계적으로 잡히는 위반만 확인하며, 전체 화면의 스크린리더 실사용성을
  포괄적으로 검증한 것은 아니다.

## 7차 마일스톤(알파 인프라)에서 새로 드러난 한계

- **실제 배포·사용자 0명** — 이번 마일스톤은 알파 테스트에 곧바로 쓸 코드 인프라만
  만들었다. 실제 호스팅·PostgreSQL 프로비저닝·테스터 모집·실사용자 인터뷰는 진행하지
  않았다(`docs/ALPHA-PLAN.md`).
- **상영관 접근성 데이터 필드 자체가 없다** — 데이터 완성도 채점(`docs/DATA-QUALITY.md`)이
  이 항목을 아예 제외한 이유이자, 추천 폼의 `wheelchair` 조건이 항상 모든 관을 하드
  필터로 제외하는 이유다.
- **검색은 단순 부분 문자열 매칭**(`docs/DEVELOPMENT.md`가 아니라 코드 자체 원칙) — 오타
  교정·형태소 분석·유사도 기반 검색은 없다. LLM 기반 검색도 의도적으로 배제했다.
- **예매 링크 검증은 표본 점검이지 실시간 모니터링이 아니다** — `npm run maintenance:links`를
  수동/배치로 돌려야 갱신되며, 페이지 본문은 절대 읽지 않으므로 "만료" 판정은 상영
  시각 경과 여부에 의존한다(HTTP 상태만으로는 만료를 구분할 수 없는 경우가 있다).
- **데이터 보존·삭제 정책이 확정되지 않았다** — 지금은 대부분 append-only 무기한 보존이다
  (`docs/DATA-RETENTION.md`). 실제 사용자가 생기기 전 법률 검토가 필요하다.
- **온보딩·기능 플래그는 최소 구현**이다 — 온보딩 3문항 답은 이 브라우저에만 남고
  서버로 전송되지 않는다(장기 프로필 없음). 기능 플래그는 단일 관리자 전제라 변경자
  구분이 `actor='admin'` 고정값 수준이다.
