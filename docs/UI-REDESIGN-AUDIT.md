## 화면별 감사 결과

### 홈 (`/`)

- **베타 경고가 CTA보다 시각적으로 강하다(모바일에서 특히)**: 경고 카드가 탠(warm tan) 배경
  채움색을 쓰고, 정작 그 아래 "추천 시작하기" 버튼보다 리딩 순서상 먼저 온다. 모바일에서는
  경고 카드의 색 대비가 CTA보다 눈에 먼저 들어온다.
- **실제 버그 발견(디자인과 무관)**: 모바일 캡처에서 온보딩 카드의 "4DX 멀미, 얼마나 신경
  쓰이세요?" 질문 버튼들이 하단 고정 모바일 내비게이션 바에 가려져 있다(z-index/여백 문제로
  추정 — 리디자인과 별개로 실제 회귀 버그, Stage 1에서 같이 고친다).
- **추천 가능 영화 목록이 순수 텍스트 링크 목록**: 제목+연도+화살표뿐, 화면비·포맷·비주얼
  요소 전혀 없음 — Stitch 레퍼런스(`_1`, `_3`)의 backdrop 이미지 + 화면비 배지 + "추천됨"
  라벨 + 상영관명 조합과 대비된다.
- 온보딩 카드가 히어로 바로 아래 별도의 큰 카드로 존재 — §6 지시대로 추천 시작 흐름에
  자연스럽게 통합 필요.
- "이렇게 추천해 드려요"(3단계, 아이콘 카드)와 "CineFit이 비교하는 것들"(불릿 목록)은 이미
  서로 다른 레이아웃을 쓰고 있어 이 항목은 생각보다 덜 시급하다 — 다만 둘 다 톤이 플랫하다.
- 우측 히어로 일러스트(스크린+좌석+빛)는 이미 "추상적 시네마 비주얼" 방향과 부합 — 유지·확장.
- 전체적으로 파란색 단일 브랜드 컬러 + 기본 sans 폰트 + 균일한 rounded border card 반복 —
  "Cinematic Editorial Utility"가 요구하는 타이포그래피 중심·hairline 구분선·warm off-white
  캔버스와는 거리가 멀다.

### 영화 선택 (`/movies`)

- **가장 명확한 "사양 목록처럼 보인다" 사례**: 카드 하나에 기본 화면비·IMAX 확장 화면비·돌비
  애트모스 믹스·촬영 포맷·배급 포맷 버전이 각각 자체 신뢰도 배지+확인일과 함께 나열된다 —
  CTA 버튼에 도달하기 전에 5개 항목의 기술 스펙을 다 읽어야 한다.
  AspectFrame(스크린+커튼 일러스트)은 세 카드가 완전히 동일한 그래픽이라 구분 요소가 아니라
  장식에 가깝다.
- 검색·상태 필터가 화면 상단에 없다(§7 요구사항).
- 베타 경고가 여기서도 페이지 최상단, 제목 바로 아래에 탠 배경으로 등장 — 홈과 동일 패턴.

### 검색 (`/search`)

- **입력 전 화면이 완전히 비어 있다**(`app/search/page.tsx` 확인: `q`가 없으면
  `results = { movies: [], cinemas: [] }`이고 렌더링되는 건 제목+입력창뿐). 예시 검색어·인기
  영화·주요 상영관·최근 검색 등 아무 안내도 없음 — §11이 지적한 문제 그대로.
  결과 리스트(입력 후)는 기능적으로는 잘 동작하지만 흰 바탕의 평범한 border card 목록이라
  "내부 도구처럼 보인다"는 지적과 일치.

### 추천 조건 입력 (`/recommend/[id]`)

- 영화 요약 + 1단계(일정/위치) + 2단계(기준) + 3단계(피하고 싶은 조건)가 **4개의 개별 카드로
  세로로 쌓여 있다** — §8이 지적한 "설정 페이지" 인상 그대로.
- 캡처에서 "추천 받기" 버튼이 1단계 카드 바로 뒤에 등장하는 것처럼 보이는데, 이는 실제 UI가
  아니라 **sticky 버튼을 fullPage 스크린샷이 스크롤 위치 그대로 박아넣는 촬영 아티팩트**로
  보인다(실제 스크롤 시 하단 고정으로 보일 가능성이 높음) — Stage 2에서 실제 브라우저로
  재확인 필요.
- 우측 summary 패널이나 모바일 sticky bar 형태의 "지금까지 고른 조건 요약"이 없다(§8 요구사항).

### 추천 결과 (`/results`) — 가장 중요한 화면

- **1순위·2순위·3순위가 완전히 동일한 크기·구조의 카드 3개**로 나란히 배치되고, 1순위는
  파란 테두리 강조와 작은 "가장 잘 맞아요" 배지만 다르다 — §9가 지적한 "위계 없음" 문제의
  가장 뚜렷한 사례.
- 각 카드 안에 "잘 맞는 이유"(불릿)·"고려할 점"·"확인 필요"·확인일 배지·"점수는 어떻게
  계산되나요?" 토글·피드백 버튼 5개가 3번 반복 — 정보 밀도가 매우 높다.
- 하단 비교 표는 실제로 유용하지만 종합 점수·포맷 만족도·상영관 품질·이동·가격·정보
  신뢰도·확신도가 전부 텍스트/숫자로만 표시 — 시각적 스캔이 어렵다(§9의 "horizontal score
  bars" 요구와 대비).
- Stitch 레퍼런스 `_5`(Recommendation Results)가 정확히 이 화면의 목표 구조를 보여준다: 큰
  히어로(사진+MATCH%+제목+"Why this fits" 산문+4-metric row+기술 사양+좌석맵+BOOK
  버튼) + 아래 작은 "ALTERNATIVE COMPARISONS" 2장(라벨+match%+짧은 산문+3-metric
  row+outline 버튼). 실제 극장 사진은 저작권 문제로 못 쓰므로, 히어로 이미지 자리는 홈의
  추상 일러스트와 같은 계열의 화면비/좌석 그래픽으로 대체한다.

### 상영관 상세 (`/cinemas/[id]`)

- **기술 문서처럼 보인다는 지적이 정확하다**: "현재 사양"이 raw key-value 표(영사기/스크린/
  사운드/표시 가능한 최대 확장비/마스킹)이고, "근거 기록" 섹션은 `projector.imax_grade`,
  `gt_dual_laser` 같은 **내부 필드명·enum 원문을 그대로 사용자 화면에 노출**한다 — §14 위반
  사례. 기본 화면에서 바로 보이면 안 되고 "왜 이 정보가 표시되나요?" 뒤로 숨겨야 한다.
  (§10 "이력과 출처" 요구사항과 정확히 일치하는 문제.)
- 좌석 존은 이미 목적별 배지(몰입/사운드/목 편함/자막 가독 등)로 구성돼 있어 §10 요구와
  방향은 맞다 — 다만 시각적으로는 여전히 border card + 배지 나열 수준.
- 상영관 프로필이라기보다 스펙시트 — Stitch `_7`(Theater Technical Profile)의 구조(큰 이름
  헤더+2 CTA, 5칸 대형 메트릭 그리드, 좌석 품질 인덱스 그리드+캡션, "DATA INTEGRITY &
  UPDATES" 요약 + 별도 "제보" 콜아웃 박스)가 좋은 목표 지점이다.

### 출처 (`/sources`)

- **일반 사용자용 설명이 아예 없다**: 페이지가 시작하자마자 "8단계 신뢰도" 배지 목록과 출처
  표(신뢰 가중치 숫자 1.00/0.85/0.50/0.30 그대로 노출)로 들어간다 — §12가 요구하는 "CineFit이
  정보를 검증하는 방법"에 대한 쉬운 설명이 상단에 없다.
- **개발 내부 경로가 프로덕션 화면에 노출되는 실제 문제 발견**: 페이지 하단에
  `docs/90-verification-register.md`라는 저장소 내부 문서 경로가 링크 텍스트로 그대로
  찍혀 있다. 이건 디자인 문제가 아니라 §14가 명시적으로 금지하는 "개발 문구 노출"의 구체적
  사례이며 리디자인과 무관하게 반드시 제거해야 한다.
- 가중치·출처 상세는 기본 화면이 아니라 펼치기 뒤로 이동해야 한다(§12).

### 사용자 제보 (`/cinemas/[id]/report`)

- 기능적으로 잘 동작하고 번호 매긴 3단계 카드 구조 — 추천 조건 입력 화면과 동일한 패턴이라
  일관성은 있으나 같은 "쌓인 카드" 인상을 공유한다. 이 화면은 유틸리티 폼이라 에디토리얼
  톤을 억지로 입히기보다 공통 토큰(색·타이포·버튼)만 맞추는 정도로 충분하다고 판단.

## 레거시 CSS 감사 (`app/globals.css`)

- `.card`, `.btn`, `.btn-primary`, `.field`, `.notice`, `.row`, 전역 `main` 셀렉터가 여전히
  존재하며 관리자 화면(`app/admin/**`) 전용으로 쓰인다. 사용자 화면(`app/(user-facing)` 상당)은
  이미 Tailwind 유틸리티 클래스를 직접 쓰고 있어 실제로는 두 시스템이 화면 단위로는 잘
  분리돼 있다(우려했던 것보다 혼재가 적다) — 다만 사용자 화면 쪽 Tailwind 토큰 자체가
  "Cinematic Editorial Utility"에 맞게 재정의돼야 한다(§4, 다음 작업에서 진행).
