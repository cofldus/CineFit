# UX 가이드라인 (구현 기준)

- 기준일: 2026-07-28 | 관련: [DESIGN-SYSTEM.md](./DESIGN-SYSTEM.md), [09 UX/UI](./09-ux-ui.md)

## 1. 톤 & 문구

- 정중체·평서문, 사용자 관점 질문형 헤더("어떤 조건을 원하세요?", "무엇이 잘못됐나요?").
- 개발자 용어·DB enum을 그대로 노출하지 않는다: `FilmFormatMatch` → "포맷 만족도",
  `SeatQuality` → 좌석 관련 축은 "좌석 존" 문맥으로만 노출, DB 상태값(`user_report`,
  `estimated` 등)은 `INFO_STATUS_LABELS`(TrustBadge)로 항상 한국어 라벨을 거친다.
- 전문 용어(확장 화면비·마스킹·CoLa·GT 등)는 별도 팝오버 대신 문맥 설명 문장으로 풀어
  쓴다(예: "GT 비율(1.43) 스크린이라 1.43:1 콘텐츠를 풀사이즈로 못 보여준다").

## 2. 화면별 원칙

- **홈**: 5초 안에 무엇인지·뭘 입력하면 되는지·베타 상태를 전달. 히어로는 자체 SVG
  비주얼(포스터·로고 없음)만 사용. 3단계 흐름 설명(영화 선택/조건 입력/이유 있는 추천)은
  실제 백엔드 동작과 1:1로 대응하는 문구만 쓴다.
- **영화 선택**: 카드가 포스터 없이도 비어 보이지 않도록 AspectFrame(실제 화면비 시각화)
  을 최상단에 둔다. 그리드는 모바일 1열/태블릿 2열/데스크톱 3열.
- **조건 입력**: 실제 `RecommendationRequest` 필드만 재배치한다 — 존재하지 않는 축
  (개별 화면/사운드 슬라이더 등)을 UI에서 만들어내지 않는다. 3단계 구획(언제·어디서 /
  무엇이 중요한지 / 피하고 싶은 것)은 시각적 안내일 뿐 폼 제출은 여전히 한 번에 이뤄진다.
- **추천 결과**: 1순위 카드만 `border-primary` + `shadow-highlight` + "가장 잘 맞아요"
  배지로 강조하고, 2·3순위와 과도하게 차이 나는 레이아웃(카드 크기 차등 등)은 쓰지
  않는다 — 광고 카드처럼 보이지 않게 하라는 요구를 지킨다. 점수 상세에는 항상
  "절대 품질이 아니라 지금 조건에서의 상대적 적합도"임을 명시한다. pros/cons/uncertainties
  는 "잘 맞는 이유/고려할 점/확인 필요" 헤더로 항상 구분해서 보여준다(레이블 없는
  나열 금지).
- **상영관 상세**: 데스크톱에서 "현재 사양"과 "목적별 좌석 구역"을 2열로 배치해 한
  화면에서 비교 가능하게 한다. 제보 진입점은 페이지 상단 1곳 + 관련 섹션(좌석 구역) 1곳,
  최소 2곳에 배치한다.
- **제보 폼**: 한 화면 안에서도 번호 배지(①②③)로 "무엇이 잘못됐나요 → 올바른 정보는
  무엇인가요 → 언제·어떤 근거로 확인했나요" 흐름을 시각적으로 구분한다. 실제 다단계
  마법사로 화면을 나누지는 않았다(필드 수가 적어 스크롤 한 화면으로 충분하다고 판단).

## 3. 모바일 내비게이션

- 하단 내비(`MobileNav`)는 홈/영화/출처 3탭만 유지한다 — 관리자 링크는 절대 넣지 않는다.
- `/recommend/[id]`는 폼 자체의 sticky 제출 바가 화면 하단을 차지하므로 하단 내비를
  숨긴다(둘이 겹치면 실수 탭 유발). 다른 화면은 항상 하단 내비를 보여준다.
- 데스크톱(`sm` 이상)은 상단 헤더 내비만 쓰고 하단 내비는 숨긴다.

## 4. 남은 항목 (이번 마일스톤에서 다루지 않음)

- 영화 검색/자동완성, 온보딩, 마이페이지, SeatMapViewer(좌표 기반 좌석도) — 문서 09가
  구상한 14화면 중 이번에 실제로 다시 그린 범위는 홈/영화/조건 입력/결과/상영관 상세/
  출처/제보뿐이다. 나머지는 애초에 구현되지 않았으므로 리디자인 대상도 아니다.
- CompareTable 모바일 카드형은 속성별로 3개 픽 값을 나란히 보여주는 1차 구현이다 —
  상영관명이 반복돼 다소 빽빽해 보일 수 있어 후속 개선 여지가 있다(docs/BETA-LIMITATIONS.md).
